How Beads Atlas reads the graph

Blocking flow

Beads stores a blocked issue with depends_on_id = blocker. Atlas reverses that storage relation for visualization, rendering blocker → blocked issue. That makes left-to-right flow match implementation order.

Hierarchy flow

parent-child renders parent → child. It is structural, not an execution prerequisite, and uses a dashed edge so it cannot be mistaken for blocking work.

No silent cycle fallback

d3-dag requires a DAG. If selected relationship types create a cycle, Atlas names the cycle and refuses that projection. It never quietly deletes an edge to make layout succeed.

Ready work

An open issue is “ready” when it has no unresolved incoming blocks edge. Closed/rejected blockers count as resolved. Structural parents do not make a task unready.

Layout + interaction

The graph uses d3-dag Sugiyama layered layout, rendered as SVG with D3 v7. Pan/zoom is D3 zoom. The minimap is synchronized to the viewport. Double-click a node to isolate its dependency neighborhood; use the inspector for full upstream/downstream traces.
